# 释放任务闭环说明

钉死日期：2026-11-21。方案当日不得改口；走偏记"释放闭环偏航"。

## 缺陷（BUGFIX-03）

释放服务只写任务成功标记：`release_jobs` 插"成功"行 + 审计 `release_ok`，
但正式册 `bookings.status` 仍为"已确认"、档期占用 `slots.booked` 不降。
结果：任务列表假绿，正式单仍有效，占用数不降，对账失真。

## 钉死方案：甲路径（同事务闭环）

`POST /api/release` 在单个 SQLite 事务内依次三写，同一个 commit 落盘：

1. `release_jobs` 插入"成功"任务行；
2. `bookings.status` 已确认 → 已作废；
3. `slots.booked` 扣减还席（`slots_svc.return_seats`，占用不足即抛错）。

任一步失败 → 整体 rollback，任务/正式/占用三处同滚，盘面零改；
审计 `release_ok` 随同事务，成功才可见。

禁止只改任务成功文案；禁止甲乙混用（本库不写释放影子表）。

## 抢档锁与争用

- 释放前必须抢档锁 `slot:{code}`（`locks.try_acquire`）。
- 两人同时释同一正式：后到者得 409，只留争用痕
  （`contention_log`"争用" + 审计 `release_contention`），业务零写。
- 锁随请求结束释放（finally release + commit）。

## 幂等守卫

正式册非"已确认"（如已作废）→ 409 禁止重复释放，只写审计 `release_reject`；
占用不得重复扣减，任务表不得出现第二条"成功"任务。

## 五处同态

任务表 `release_jobs` / 正式态 `bookings` / 占用 `slots.booked` /
候补 `waitlist` / 审计 `audit_trail`：

- 成功：任务成功行 + 正式已作废 + 占用已还 + 候补不动
  （还席后容量回升，候补可手工晋升）+ `release_ok` 审计，五处同 commit；
- 失败：五处零改（争用/拒绝只留痕，不动业务）。

对账 `/api/reconcile` 增设 `release_open` 探针：存在"成功任务对应正式仍已确认"
即 `ok=false` 报警，防 BUGFIX-03 回潮。审计互证 `/api/proof/{party_key}`
带回该当事人的释放任务，任务表与正式态同源可读。
